# Фиды WO для поиска и сетей

Новые скрипты работают отдельно. `filter_feed.py`, `blocked_vendors.txt` и существующий `.github/workflows/update-feed.yml` не изменены. Основной фид и его Latest release продолжают работать как раньше.

## Что делает фильтрация

1. Берет **весь текущий фид** `https://williamsoliverfeed.rta.workers.dev/feed.xml`, в котором уже выполнена прежняя обработка.
2. Повторно проверяет бренды по текущему `blocked_vendors.txt`, используя ту же нормализацию, что и существующий скрипт.
3. Поиск сверяет `offer id` со вкладкой **WO / Поиск** (gid `708485822`), сети — со вкладкой **WO / Сети** (gid `0`).
4. Исключает товар, если в соответствующей вкладке у него **строго больше 1000 показов**.
5. Товары с **ровно 1000**, меньшим числом показов и отсутствующие в таблице сохраняются. Новый ассортимент берется из основного фида, а не из списка строк таблицы.
6. Сохраняет ID, categoryId, категории, бренды, цены, остатки и все остальные данные оставшихся товаров. XML может отличаться способом экранирования и сериализации, но данные сохраняются.

ID всегда строковые, начальные нули сохранены. Строки каталогов/брендов, у которых вместо товарного ID строка вроде `brands/...`, пропускаются. Если ID повторяется, строка с показами >1000 исключает его; другая строка с меньшим числом не отменяет исключение. Показы повторяющихся строк не суммируются.

## Файлы

- `filter_search_feed.py` — запуск генератора для поиска
- `filter_networks_feed.py` — запуск генератора для сетей
- `segment_feed.py` — общая логика этих двух генераторов
- `worker_search.js` — полный скрипт для отдельного Cloudflare Worker поиска
- `worker_networks.js` — полный скрипт для отдельного Cloudflare Worker сетей
- `.github/workflows/update-segmented-feeds.yml` — отдельное автоматическое обновление
- `segmented_feeds.json` — ссылки на последние проверенные результаты, создается автоматически после первого успешного запуска

Python использует только стандартную библиотеку. У Worker нет npm-зависимостей, токенов, KV или других bindings. Тяжелая обработка XML выполняется в GitHub Actions, Cloudflare передает готовый файл потоком.

## Как создать ссылки в Cloudflare

1. В GitHub открой **Actions → Update segmented feeds**. Дождись зеленого запуска. Если его нет, выбери **Run workflow → main → Run workflow**.
2. Создай **новый** Cloudflare Worker для поиска. В **Edit code** полностью замени стартовый код содержимым `worker_search.js`, затем **Deploy**.
3. Создай второй **новый** Worker для сетей, вставь весь `worker_networks.js` и нажми **Deploy**.
4. У каждого Worker итоговая ссылка — его собственный адрес с `/feed.xml`. Этот адрес можно использовать в Директе.

Не заменяй код существующего Worker `williamsoliverfeed`: он остается источником для новых фидов.

## Обновления и изменение порога

- Автоматический запуск: каждые 6 часов, в 00:43, 06:43, 12:43 и 18:43 UTC (03:43, 09:43, 15:43 и 21:43 МСК). Это на 20 минут позже расписания существующего обновления основного фида.
- После изменения статистики в Google таблице можно сразу запустить **Actions → Update segmented feeds → Run workflow**. Иначе изменения попадут в следующий запуск по расписанию.
- Для постоянного изменения порога поменяй `MAX_IMPRESSIONS = 1000` в соответствующем `filter_search_feed.py` или `filter_networks_feed.py` и закоммить в main. Сборка запустится автоматически. В Worker менять ничего не требуется.
- При изменении `blocked_vendors.txt` новая сборка также запускается автоматически. Исключенные старым фильтром бренды остаются исключенными, поскольку источник — уже обработанный фид.
- Сохраняй доступ Google таблицы для чтения по ссылке: GitHub Actions скачивает CSV без Google-авторизации.
- При ошибке таблицы, источника, проверки XML или публикации ссылки на последнюю успешную версию остаются прежними. Worker не возвращает исходный нефильтрованный фид вместо результата.
- Новые releases публикуются с `--latest=false`: они не меняют Latest, используемый текущим фидом.

## Локальный запуск

```bash
python3 filter_search_feed.py --output feed_search.xml
python3 filter_networks_feed.py --output feed_networks.xml
python3 -m unittest discover -s tests -v
```

Для разового порога при локальном запуске: `--threshold 1500`. В расписании применяются значения MAX_IMPRESSIONS из файлов.
